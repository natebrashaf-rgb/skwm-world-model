# RSSM 消融实验报告

## 实验目的与总体结论

本实验在项目真实状态数据上，对 RSSM V3 的关键模块进行可控消融，而不是仅调用一个封装好的模型。实验入口为 `run_rssm_ablation.py`，模型内部显式暴露编码器、确定性循环状态、随机隐状态、先验、后验、解码器、对数变换和 KL 损失权重。

结果显示，当前实现中**随机隐状态和确定性循环状态都是必要模块**：分别去掉后，模型无法形成有效的主题排序，Spearman 相关性和 P@10 降为 0。当前数据规模和训练预算下，`no_log` 配置在数值指标上优于默认 `full` 配置；但这项结果需要谨慎解释，因为原始热度是非负计数，未进行对数变换时目标分布更偏向高热度主题，可能放大水平 MAE 与排序指标之间的差异。增加历史窗口到 12 年、将随机潜变量维度提高到 64，以及去掉动态 KL 项，在本次单种子实验中对部分 horizon 有改善；去掉表征 KL 项影响较小。

这些结果是**消融方向性证据**，不是最终论文结论。每个消融配置本次使用一个固定种子 42 和 300 个训练步骤，后续应对主要配置使用五种子重复实验。

## 消融配置

| 配置 | 改动 |
|---|---|
| `full` | 随机隐状态、确定性循环状态、对数变换均启用；T=8、stoch=32、动态 KL=1、表征 KL=0.1 |
| `no_stoch` | 去掉随机隐状态，仅保留确定性路径 |
| `no_deter` | 去掉确定性循环状态，循环状态被固定为零 |
| `no_log` | 取消 heat、centrality、connections 的 log1p 变换 |
| `window4` | 历史窗口 T=4 |
| `window12` | 历史窗口 T=12 |
| `stoch8` | 潜变量维度为 8 |
| `stoch64` | 潜变量维度为 64 |
| `no_dyn_kl` | 动态 KL 权重为 0 |
| `no_rep_kl` | 表征 KL 权重为 0 |

当前 RSSM 代码中没有独立的“语种条件向量”输入通道。动作向量 `a_dim=4` 代表干预编码，并非语种条件；因此本轮没有伪造一个 `no_language_condition` 结果，而是将其记录为**待扩展的结构性消融**。

## 结果解释

`no_stoch` 和 `no_deter` 的退化最明显。去掉随机隐状态后，模型无法利用先验分布表达未来状态的不确定性；去掉确定性循环状态后，先验只依赖近似固定的状态，因而无法有效积累历史动态。两种配置的预测排序几乎退化为常数或固定排序，这解释了 Spearman 和 P@10 为 0。

`no_log` 在本轮训练预算下表现最佳，h1、h3、h5 的 MAE 分别为 16.228、20.455、23.322。由于 log1p 会压缩高热度主题，取消变换可能更有利于当前的原始计数 MAE；但这并不自动证明无变换具有更好的泛化性。应在五种子和标准化对照下重复，并同时报告原始空间和变换空间损失。

窗口长度的影响依赖预测跨度。T=4 在 h1 上略优于 full，T=12 在 h3 和 h5 上略优于 full，说明较长历史可能对中长期预测有帮助，但收益较小。stoch=64 在 h3、h5 上略优于 full，stoch=8 则略差，提示潜变量容量不足可能限制长期动态表达。

去掉动态 KL 项后，MAE 在三个 horizon 均下降，尤其是 h3；但 KL 正则项的作用不仅是降低 MAE，还包括约束先验与后验的一致性。该结果应结合潜变量 KL、rollout 稳定性和多种子结果判断，不能仅依据单次 MAE 选择模型。去掉表征 KL 项的变化很小，说明在当前训练步数下该项贡献有限，或者其效果被其他损失项覆盖。

## 训练稳定性

所有配置均完成 300 步训练，loss 保持有限值，没有 NaN、Inf 或训练中断。默认 full 配置的 loss 从 2.157 降至 1.301；no_log 从 42.172 降至 6.095；no_stoch 从 0.968 降至 0.763；no_deter 从 2.283 降至 1.448。no_log 的原始空间数值尺度明显更大，因此不能直接将不同配置的训练 loss 横向比较，只能在相同目标变换下比较。

## 实验产物与复现

运行命令：

```bash
python3 run_rssm_ablation.py --steps 300 --batch 128
```

输出目录为 `output/rssm_ablation/`，其中包含每个配置的模型检查点、训练日志、逐评测年份预测文件，以及总汇总文件 `ablation_summary.json`。运行器默认使用真实数据，并在结果中记录数据来源和训练配置。

## 限制与后续工作

本实验每个配置只运行一个种子，且训练步数为 300，适合发现结构性退化和候选方向，不足以支持显著性结论。下一步应至少对 `full`、`no_log`、`window12`、`stoch64`、`no_dyn_kl` 运行五种子，并固定相同的训练步数、评测窗口和主题集合。

同时需要补充标准化版本、真实语种条件向量版本，以及严格的 horizon-specific 训练/评估协议。特别是当前 h1/h3/h5 结果使用不同评测年份集合，报告中应继续明确这一点；若用于论文，建议增加配对 bootstrap 或按评测年份进行的置信区间，而不是只报告单次均值。
